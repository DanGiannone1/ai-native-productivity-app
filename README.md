## What This Is

A FastMCP server that allows Claude to dynamically create and manage each user's unique productivity data model. Users describe their mental model in natural language; Claude translates this into appropriate schemas and manages their data via MCP tools.

**The Problem:** Every productivity app forces users into a rigid structure (tasks, projects, tags). But people think differently—some use habits and streaks, others goals and milestones.

**The Solution:** Let Claude create the perfect productivity model for each user on-the-fly.

## Quick Start (Local Development)

### Prerequisites
- Python 3.11+
- Azure Cosmos DB account (or create one via setup script)
- [UV package manager](https://docs.astral.sh/uv/)
- Azure CLI (for infrastructure setup)

### Installation

**1. Clone and install dependencies:**
```powershell
cd C:\projects\productivity
uv sync
```

**2. Setup Azure infrastructure (creates Cosmos DB, etc.):**
```powershell
.\deployment\scripts\setup-infrastructure.ps1 -Environment dev
```

This creates:
- Resource groups (shared, dev, prod)
- Cosmos DB (serverless mode)
- Log Analytics workspace
- Updates `.env` with connection details

**3. Initialize database:**
```powershell
.\run_local.ps1 init
```

**4. Seed sample data (optional):**
```powershell
.\run_local.ps1 seed
```

**5. Start MCP server:**
```powershell
.\run_local.ps1 mcp
```

Server starts on `http://localhost:8000`

### Configuration

The `.env` file is auto-generated by `setup-infrastructure.ps1`:

```env
# Environment
ENVIRONMENT=dev

# Cosmos DB
COSMOS_HOST=https://your-cosmos-dev.documents.azure.com:443/
COSMOS_KEY=<auto-generated>
COSMOS_DATABASE=productivity
COSMOS_CONTAINER=productivity-data

# Development Mode (auth disabled for MVP)
DISABLE_AUTH=true
DEFAULT_USER_ID=dev-user

# Logging
LOG_LEVEL=INFO
```

**See:** [deployment/README.md](deployment/README.md) for infrastructure details

## Architecture Overview

### Core Concepts

**1. Schema Flexibility**
- Users define their own entity types (tasks, goals, habits, custom types)
- Claude interprets user intent and creates appropriate schemas
- Each user has isolated data (partitioned by `userId`)

**2. Multi-Document Cosmos DB Design**
- **Schema documents**: Store entity type definitions (`id: "schema:{userId}"`)
- **Entity documents**: Store individual instances (`id: "{entityType}:{uuid}"`)
- Partitioned by `/userId` for efficient queries and isolation

**Benefits:**
- Scales indefinitely (no 2MB document limit)
- Efficient queries (single-partition, low RU cost)
- Update one entity without loading all data

**3. MCP Protocol**
- Claude Desktop/MCP Inspector connects to server
- 10 core tools for schema and entity management
- JSON-based request/response

**See:** [src/README.md](src/README.md) for detailed architecture

## MCP Tools

**Schema Management:**
- `create_entity_type` - Define new entity types
- `get_user_schema` - View all entity type definitions
- `update_entity_type` - Modify existing schemas
- `delete_entity_type` - Remove entity types

**Entity CRUD:**
- `create_entity` - Create new entities
- `get_entity` - Retrieve by ID
- `update_entity` - Modify entities
- `list_entities` - Query with filtering/sorting
- `delete_entity` - Soft or hard delete
- `count_entities` - Count entities of a type

**See:** [src/README.md](src/README.md) for tool implementation details

## Usage Example

**Scenario:** User wants to track daily habits

**1. Claude creates a habit schema:**
```python
create_entity_type(
    "habit",
    {
        "name": {"type": "string", "required": True},
        "frequency": {"type": "enum", "enum_values": ["daily", "weekly", "monthly"]},
        "streak": {"type": "number", "default": 0},
        "lastCompleted": {"type": "datetime"}
    }
)
```

**2. Claude creates habit entities:**
```python
create_entity("habit", {
    "name": "Morning meditation",
    "frequency": "daily",
    "streak": 7
})
```

**3. Claude queries habits:**
```python
list_entities("habit", sort_by="streak", sort_descending=True)
```

**See:** [Root README examples section](#usage-examples) or [tests/README.md](tests/README.md) for more examples

## Troubleshooting

**Server won't start:**
- Check `.env` file exists and has Cosmos DB credentials
- Run `uv sync` to install dependencies
- Run `.\run_local.ps1 init` to verify Cosmos DB connection

**Database connection fails:**
- Verify `COSMOS_HOST` and `COSMOS_KEY` in `.env`
- Check Azure Cosmos DB firewall (allow local IP)
- Test connection: `.\run_local.ps1 init`

**Tests fail:**
- Ensure database initialized: `.\run_local.ps1 init`
- Check Cosmos DB connection
- Review test output for specific errors

**See:** [deployment/README.md](deployment/README.md#troubleshooting) for infrastructure troubleshooting
